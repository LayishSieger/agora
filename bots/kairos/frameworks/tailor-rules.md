# Tailor rules — Kairos

Disclosed framework. Read when selecting evidence and rewriting bullets.

Agora-adapted from the public offer-toolkit resume-tailoring rules. English only. No third-party branding. **One** job-specific resume per company/role (not a three-version pack).

---

## 1. Iron rules

1. **Never fabricate** — no new employers, titles, dates, metrics, skills, or duties. Reorganize, emphasize, and translate wording only from masters + true evidence.
2. **Never inflate verbs** — "contributed" / "participated" must not become "led" / "owned" unless the master text already supports that scope. Interview follow-ups will expose inflation.
3. **Use JD words when facts match** — if the master says "improved performance" and the JD says "optimized latency", and the fact is the same work, prefer the JD phrasing.
4. **Keep real numbers** — preserve master metrics. Do not invent ranges. If a number is missing and would help, ask the user; do not guess.
5. **Influence > action > tool** — lead with outcome/scope, then judgment/action, then tools.
6. **Cut to fit** — job resumes are short. For every bullet you promote, drop or compress equal weak content. Do not grow forever.
7. **Masters stay untouched** — write only under `applications/`. Never edit `master-resume.md`, `profile.yaml`, `preferences.yaml`, or `story-bank.md`.

---

## 2. Preference hints

Read from `preferences.yaml` when present:

| Hint | Use |
|---|---|
| `emphasize` | Prefer bullets/tags that support these themes when true on masters |
| `de_emphasize` | Compress or omit matching experience when not required by the JD |
| `resume_voice` | Tone (e.g. direct, evidence-led). Never invent facts to match tone |

Hints never create facts. If a hint conflicts with honesty, honesty wins.

---

## 3. Rewrite strategy (before writing)

From the jd-bank entry (must-haves, nice-to-haves, hidden signals) and masters, decide:

1. **3 keywords** from Must-haves that should appear in title/skills/bullets (only if true).
2. **1 core narrative** the resume should center (one line).
3. **Reorder / rewrite / compress** plan per experience block.

Tell the user this strategy briefly if they are in the loop; then write.

---

## 4. Structure (one resume)

Order for Senior+ IC (adjust only if masters lack a section):

1. Name + contact (from `profile.yaml`)
2. Headline / summary (1–3 lines; position as the JD’s target using true facts)
3. Experience (most relevant first; compress early/irrelevant to one line)
4. Education (short for Senior+)
5. Skills (JD hard skills the candidate truly has; JD wording when honest)
6. Selected projects (only if they strengthen Must-haves)

Standard section titles: Experience, Education, Skills (and Projects if used). Single-column markdown. No tables-as-layout, no image text, no bilingual pack.

### Experience bullets

- Front-load the **most JD-aligned** 1–2 bullets per role (Must-haves first).
- Prefer **problem → judgment → action → result** when masters support it.
- Surface **hidden-signal** traits (ownership, ambiguity, influence) only with evidence.
- Keep 1–2 honest hook details an interviewer can probe — do not invent them.

---

## 5. What not to do

- Keyword stuffing (same token glued on every bullet)
- Buzzwords without evidence (synergy, passionate, team player as filler)
- Three parallel resume versions (ATS / Recruiter / HM packs) — Agora writes **one** tailored resume
- Third-party brand footers or bilingual marketing shells
- Auto-forward to Melete after tailor (G4)

---

## 6. Checklist (before sole-write)

- [ ] Every bullet traces to a master fact (or user-confirmed addition via Mneme — not invented here)
- [ ] No verb inflation vs masters
- [ ] Must-have keywords present where facts support (title / skills / ≥1 bullet)
- [ ] Preference hints honored without fabricating
- [ ] Gaps left honest (omit or note; do not invent coverage)
- [ ] English only; no third-party footer
