# ADR 0015 — Agora may fetch its own blueprint onto disk; Grok skills stay the Add snapshot

Fetch-blueprint used to refuse slug `Agora` so the installer could not pull itself from GitHub. Playbooks such as `prompts/out-of-scope.md` are not Grok skills and do not copy on template Add, so a thin recipe had no disk file to follow. We lift **Not Agora** for **disk self-materialize only**: first-run (and later a missing playbook) fetches the whole `bots/agora/` tree from the latest Release into `/workspace/bots/agora/` via the same zipball, atomic replace, and fail-reason contract as children (ADR 0011–0013). That is not CreateAgent Agora (`need Agora` still refuses). Enabled Grok skills remain the frozen Add recipe (`profile.md` + `first-run` / `need-bot` / `fetch-blueprint` per ADR 0004); do not re-enable or replace those slots from the zip. Child `RELEASE` refresh still asks (ADR 0008); Agora-on-disk does not.
